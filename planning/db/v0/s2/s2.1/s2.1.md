# Kidney Care — DB Design Plan (v0 / s2 / s2.1)

Date: 2026-11-12

## 1. Summary

Adds optional measurement context to `blood_pressure_readings`: cuff arm, body posture, whether it was a dialysis day, and pre/post dialysis phase. Ported from v1's `blood_pressure_log` extra fields.

## 2. Entities

| Entity | Change |
|---|---|
| `blood_pressure_readings` | + `arm`, `posture`, `is_dialysis_day`, `dialysis_phase` (all nullable) |

## 3. Key Relationships

Unchanged.

## 4. Access Patterns

Display/filter only; no new indexes.

## 5. Design Decisions

| Decision | Choice | Reason |
|---|---|---|
| Nullability | Every new column nullable; no backfill | Old rows have no context; NULL = "not recorded" |
| Dialysis encoding | `is_dialysis_day boolean` + `dialysis_phase` (`pre_dialysis`/`post_dialysis`) with consistency CHECK | Keeps v1 semantics (dialysis day without a phase is valid) while reusing v2's `pre_/post_dialysis` vocabulary from `weight_readings.dialysis_timing` |
| Value domains | CHECK constraints, not Postgres enums | Same as existing v2 tables; cheap to extend |

## 6. Open Questions

- Intra-dialysis readings (during a session) are not modelled.
