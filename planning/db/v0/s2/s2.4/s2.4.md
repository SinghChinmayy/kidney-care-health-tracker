# Kidney Care — DB Design Plan (v0 / s2 / s2.4)

Date: 2026-11-12

## 1. Summary

Adds `profiles` (username only) and the RPCs owners use to share a patient by username, change roles and revoke access.

## 2. Entities

| Entity | Change |
|---|---|
| `profiles` | New: `user_id` pk, unique `username` |

## 3. Key Relationships

- `profiles` 1:1 `auth.users`, optional (created when the user picks a username in onboarding or settings).

## 4. Access Patterns

| Pattern | Frequency | Index |
|---|---|---|
| Lookup by username | rare | unique `profiles_username_key` |
| List members | occasional | `patient_access (patient_id, user_id)` |

## 5. Design Decisions

| Decision | Choice | Reason |
|---|---|---|
| Profile visibility | RLS: own row only | v1 let every authenticated user read all profiles and exposed emails through `profiles_view`. Here other users are only reachable through RPCs returning `(user_id, username)` |
| Lookup | Exact match on normalised (`lower(trim())`) username | No prefix search → no directory browsing |
| Username format | `^[a-z0-9_]{3,30}$`, lowercase stored | Unambiguous unique handles |
| Grant | owner only; target found by username; duplicate → `already_has_access` | Owners may also grant `owner` (co-owners) |
| Revoke | owner, or the member themself (leave) | Lets caregivers/viewers drop access without bothering the owner |
| Last owner | owner rows locked `for update`, then counted | Concurrent revokes cannot both pass |
| Patient's own account | never removable; only they can change their role | People can't be locked out of their own record |

## 6. Open Questions

- Usernames are optional; members without one show as "Member" in the app.
- No audit table for access changes (only `granted_by` on the row).
