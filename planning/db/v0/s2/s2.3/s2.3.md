# Kidney Care — DB Design Plan (v0 / s2 / s2.3)

Date: 2026-11-12

## 1. Summary

Introduces `patient_access` and rewrites RLS on every app table to go through `private.has_patient_access(patient_id, min_role)`. A user can now own or access several patients; new patients are created through the `create_patient` RPC, which makes the caller owner.

## 2. Entities

| Entity | Change |
|---|---|
| `patients` | `auth_user_id` nullable (still unique); `guard_patient_update` trigger |
| `patient_access` | New |

## 3. Key Relationships

- `patient_access` M:N join between `patients` and `auth.users`, unique per pair.
- Backfill: one owner row per existing patient with an `auth_user_id`.

## 4. Access Patterns

| Pattern | Frequency | Index |
|---|---|---|
| Policy check | every row | unique `(patient_id, user_id)` |
| My accessible patients | every sync | `idx_patient_access_user` |

## 5. Design Decisions

| Decision | Choice | Reason |
|---|---|---|
| Single check function | `has_patient_access` SECURITY DEFINER, `search_path = ''`, `stable` | No recursive RLS; one place to audit |
| No client writes to `patient_access` | No policies **and** privileges revoked (`select` only) | Closes v1's self-grant-owner hole (v1 policy: `user_id = auth.uid() AND role = 'owner'` on insert, for any patient) |
| Patient creation | `create_patient` RPC only; `insert`/`delete` on `patients` revoked from `authenticated` | Owner row is created atomically; v1 also hit an RLS/RETURNING race doing this with triggers |
| Client-generated id | Optional `p_id`; repeat call by an owner returns the row, any other caller gets `patient_id_conflict` | Safe retries without letting someone claim an existing id |
| Patient soft delete | owner-only via trigger | Policy is caregiver+ for profile edits |
| Hard deletes on child tables | kept for caregiver+ | Parity with s1 policies; app uses soft delete |

## 6. Open Questions

- Offline patient creation is not supported (RPC requires network); the app creates online and then caches locally.

## 7. Change Log

- **v0/s2/s2.3** (2026-11-12): Follows s2.2. Drops the s1 1:1 user↔patient assumption.
