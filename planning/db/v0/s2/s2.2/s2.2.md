# Kidney Care — DB Design Plan (v0 / s2 / s2.2)

Date: 2026-11-12

## 1. Summary

Small metadata additions from v1: patient `blood_group`, creator attribution `recorded_by` on the four vitals/log tables, and `before_meal` in the glucose context vocabulary.

## 2. Entities

| Entity | Change |
|---|---|
| `patients` | + `blood_group` |
| `blood_pressure_readings`, `blood_glucose_readings`, `weight_readings`, `fluid_intake_logs` | + `recorded_by` (FK `auth.users`, set null on delete) |
| `blood_glucose_readings.context` | Documented vocabulary now includes `before_meal` |

## 3. Key Relationships

- `recorded_by` → `auth.users(id)`. Not a profile FK, so attribution survives users without a username.

## 4. Access Patterns

"Logged by" label on reading detail; resolved client-side against `list_patient_members` (s2.4). No index needed.

## 5. Design Decisions

| Decision | Choice | Reason |
|---|---|---|
| Who sets `recorded_by` | Trigger, from `auth.uid()` on insert; frozen on update | Brief: "set server-side or validated = auth.uid()". Server-side is simpler for clients and impossible to spoof; upserts (insert … on conflict update) keep the original author |
| Calls without JWT | Keep supplied value | Lets migrations / service-role imports attribute rows |
| Backfill | `recorded_by = patients.auth_user_id` | All pre-s2 rows were logged by the patient themself (1:1 era) |
| Glucose `before_meal` | No DB constraint | Column stays free text per s1.1; avoids rejecting unknown legacy values |
| Blood group | CHECK constraint | Same 8 values as v1 |

## 6. Open Questions

- Medication schedule / preference edits are not attributed (settings, not logs).
